- git shortlog -sn: Ver la lista de colaboradores y cuántos commits ha hecho cada uno

- git status: Muestra el PRESENTE (El estado actual del repositorio)

- git log: Muestra el PASADO (El historial de cambios)

- touch .gitignore: La palabra "touch" por sí sola es crear un archivo y el archivo creado que es .gitignore que es un archivo oculto donde Git reconoce qué archivos o carpetas debe ignorar

- git diff: Sirve para comparar y ver las diferencias exactas entre distintas versiones de tus archivos.

- git reset: Sirve para deshacer cambios o "rebobinar" el estado de tu proyecto a un commit anterior. Y tiene varios usos que son:
	1. Deshacer git add ( git reset nombre_del_archivo.ext )
	2. Deshacer Commits
		2.1: Borra los commits posteriores al Hash indicado, pero conserva todos tus cambios intactos en el Staging Area ( git reset --soft <HASH> )
		2.2: Elimina los commits posteriores, limpia el Staging Area y sobrescribe tus archivos de trabajo para dejarlos exactamente como estaban en ese commit 		     pasado. ( git reset --hard <HASH> ) únicamente en commits locales porque es PELIGROSO

- git tag: Se utiliza para marcar o etiquetar puntos específicos en el historial de commits de tu proyecto, se utiliza para marcar versiones de un sistema

- git stash: Sirve para guardar temporalmente los cambios que tienes en tu área de trabajo (modificaciones a archivos, nuevos cambios sin confirmar) sin necesidad de hacer un commit (git stash pop para recuperar esos cambios // git stash drop para eliminar los cambios guardados temporalmente)


-  git remote add origin [ link del repositorio creado en GitHub ]: Sirve para subir todo a la terminal remota, y después se hace un git push -u origin master

- git push: Se utiliza para enviar o subir los commits que has realizado en tu repositorio local (tu computadora) a un repositorio remoto

- git fetch: Descarga todos los commits, ramas y archivos nuevos desde GitHub, pero no los mezcla con tu código de trabajo. Los guarda en una "zona intermedia" o rama de rastreo remoto en tu computadora.

- git pull: Descarga los cambios desde GitHub (o el servidor remoto) y los integra directamente en tus archivos de trabajo locales en un solo paso.

- git clone: Se utiliza para descargar una copia exacta de un repositorio remoto (como uno alojado en GitHub, GitLab o Bitbucket) a tu computadora.

- Un Fork: Es una copia exacta de un repositorio remoto alojado en una plataforma en la nube

- git checkout: Sirve para viajar entre diferentes estados o versiones dentro de tu repositorio, se puede utilizar para tres tareas muy distintas que son: 
	1. Cambiar de rama ( git checkout nombre-de-rama / git switch nombre-de-rama)
	2. Crear y cambiar de rama en un solo paso ( git checkout -b nueva-rama )
	3. Moverte temporalmente a un punto específico del historial usando el Hash ( git checkout 1a2b3c4 )
🡣
🡣
🡣

- git merge: Sirve para unir el historial y el código de dos ramas diferentes en una sola.
